##ПР2. Ответы на контрольные вопросы
1. Почему для хранения денег используют decimal, а не double? Что может пойти не так с double?
double хранит число в двочисном виде, и некотыре "простые" на вид десятичные дроби (например, 0.1) не могут быть представлены в двоичной системе абсолютно точно - накапливается крошечная погрешность. Для физических расчётов это не страшно, но при работе с деньгами копейка расхождения - уже баг. decimal устроен так, что подобных проблем не возникает.


2. Что произойдёт, если целочисленный тип (например, byte) переполнится — то есть значение выйдет за границы диапазона?
произойдет переполнение (overflow). Значение "оборачивается" по кругу: если прибавить 1 к максимальному значению byte (255), результат станет минимальным возможным значением (0). Это происходит потому, что в памяти выделено фиксированное количество бит, и старший бит, отвечающий за выход за диапозон, просто теряется. 


3. Чем var отличается от динамической типизации в Python? В какой момент компилятор определяет тип переменной, объявленной через var?
var в C# - это не динамическая типизация, а неявная типизация. Тип переменной определяется компилятором один раз на этаме компиляции, исходя извыражения справа от знака =. После этого переменная имеет строго фиксированный тип, и попытка присвоить значение дркгого типа вызовет ошибку компиляции. 


4. Какой тип данных всегда возвращает Console.ReadLine(), независимо от того, что ввёл пользователь?
Console.ReadLine() всегда возвращает тип string (строку), даже если пользователь ввел число. Если нужно число, то строку придется преобразовать.


5. Чем int.Parse отличается от int.TryParse в поведении при некорректном вводе (например, буквы вместо цифр)?
int.Parse при неккоректнои вводе выбрасывает исключение FormatException, что приводит к аварийному завершению программы. int.TryParse в таком случае возвращает false, и программа продолжает работу. Это делает int.TryParse безопасным способом преобразования, когда вы не уверены в корректности ввода.


6. Что означает false, возвращённый из int.TryParse, и что при этом попадёт в переменную, переданную через out?
false озночает, что строку не удалось преобразовать в целое число (например, в ней есть буквы или она пустая). В переменную через out, в этом случае записывается значение по умолчанию для типа int, то есть 0. Если преобразование прошло успешно, метод возвращает true, а в переменную out записывается полученное число.


7. Приведите пример, когда стоит использовать TryParse, а не Parse — и объясните, почему.
TryParse стоит использовать всегда, когда данные вводит пользователь, потому что пользователь может случайно ввести буквы вместо цифр, оставить поле пустым. В этом случае Parse,  бросит FormatException, а TryParse позволит корректно обработать ошибку и попросит пользователя ввести данные заново. Пример: ввод года рождения, количества книг, номера телефона и т.д. Parse можно использовать только тогда, когда вы уверены, что строка содержит корректное число.
